# 핸들을 닫아도 영속 키가 남는 이유

정리일: 2026-10-11 · 소스 대조: bdb8bd8

## 질문의 출발점

영속 저장은 RAM에 저장하는 것인가? Object ID, 핸들, 키 지문은 왜 모두 필요한가?

### 이해가 바뀐 지점

키 객체 자체, 객체를 여는 이름, 실행 중 핸들, 공개키의 해시를 서로 구분했다. 세션 정리와 영속 객체 삭제도 별개의 동작으로 이해했다.

## 정리한 이해

임시 RSA 키 쌍 생성 → 영속 객체로 저장 → 임시 객체·핸들 정리 → 다음 세션에서 Object ID로 열기

### 임시 키를 왜 해제하는가?

영속 객체 생성에 키 속성을 제공한 뒤 사용이 끝난 임시 객체를 정리한다. 파일에 RAM 핸들 숫자를 저장하는 것이 아니다. 영속 객체의 내용을 다음 세션에서 다시 열 수 있다.

### Object ID, 핸들, 지문은 무엇이 다른가?

Object ID는 저장된 객체를 찾는 이름, 핸들은 현재 열린 객체를 API로 다루는 참조, 지문은 공개키 내용을 정해진 형식으로 해시한 값이다. 같은 이름으로 키를 교체하면 Object ID는 같아도 지문은 달라진다.

### CreatePersistentObject의 일반 데이터는 어디에 쓰는가?

키 속성 외에 애플리케이션 데이터도 저장할 수 있다. 예를 들어 버전이나 정책 메타데이터를 함께 다룰 수 있지만 갱신·권한·형식 계약이 필요하다. 현재 키 생성 경로는 별도 초기 데이터를 넣지 않는다.

### REE 파일에 있는데 왜 평문 키가 보이지 않는가?

OP-TEE 저장소는 객체를 암호화하고 무결성을 보호한다. 실제 보호는 플랫폼의 비밀키 공급과 설정에 의존한다. 숫자 파일과 dirf.db는 내부 저장 형식이며 TA 키를 파일 이름만으로 특정하지 않는다.

### 재부팅 후 키가 같으면 무엇을 확인한 것인가?

영속성과 공개키 동일성을 확인한 것이다. 과거 저장소 이미지 복원 공격에 대한 롤백 방지까지 입증한 것은 아니다. 이 둘은 별도 시험과 보호 기반이 필요하다.
